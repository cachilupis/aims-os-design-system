# AIMS OS — Does this already exist?

Almost every consistency problem in this repo has the same shape: something was
rebuilt because nobody found the version that already existed. Not because the
existing one was bad — because it was invisible.

The record, all from one week:

- **Breadcrumb** was documented as a `DS-GAP` for a month while sitting in `ui/`.
- **ProcessItem** had a full spec, five statuses and a playground, buried as
  step 5 of another page with no catalog entry. Searching "process" found nothing.
- **Stepper** was rebuilt as `BuilderTabNav` — and then rebuilt a *second* time
  by an agent who did not read the PM's open PR that had already migrated it.
- **WidgetGlyph** was written three times, in three sizes, with three icon maps
  that disagreed on 6 of 10 entries.
- **Filters** was bypassed 19 times in favour of a raw `<select>`.

None of those were laziness. Each author searched, did not find, and built.
This skill is the search that would have found them.

## Step 1 — The generated index, which now includes candidates

```bash
cat ds-index.json | python3 -m json.tool | head -60
```

`ds-index.json` is the complete inventory, regenerated by
`scripts/generate-ds-index.cjs`. Every entry carries a `tier`:

| `tier` | Means | What to do |
|---|---|---|
| `catalog` | In `ui/` or `layouts/`, specified, supported | Use it. This is the answer. |
| `candidate` | In `experimental/`, works, uses DS parts, no spec yet | **Reuse it.** It is not finished, but a second copy is worse than an unfinished first one. |

Search it by name and by concept — the thing you want may be filed under a word
you did not think of. `descriptions` are searchable text:

```bash
python3 -c "
import json,sys
q = sys.argv[1].lower()
d = json.load(open('ds-index.json'))
for c in d['components']:
    hay = (c['id'] + ' ' + c['name'] + ' ' + (c.get('description') or '')).lower()
    if q in hay:
        print(f\"{c['tier']:<10} {c['id']:<22} {c['name']}\")
" "<your term>"
```

Try more than one word. Searching \"tab\" would not have found `Stepper`;
searching \"step\" would.

## Step 2 — The widget catalog, if it is a widget

Widgets are not in `ui/`. They live in `WIDGET_DEFS` in `src/App.tsx`, surfaced
as **Patterns → Widgets** — 14 entries, each with a size class, grid widths,
states, use cases and a `dontUse` list.

```bash
grep -n 'id:\s*"' src/App.tsx | sed -n "$(grep -n 'const WIDGET_DEFS' src/App.tsx | cut -d: -f1),+80p" 2>/dev/null
```

Check the `dontUse` lines too. They frequently name the component you actually
want: Charts' `dontUse` says *"use a bar or pie chart"*, and Notes' says
*"use Activity widget instead"*.

## Step 3 — Open pull requests

The index only knows what is merged. Someone may be building it right now.

```bash
gh pr list --state open --json number,title,author,files \
  --jq '.[] | {n:.number, who:.author.login, t:.title, files:[.files[].path]}'
```

Grep those file lists for the area you are about to touch. **This step is not
optional.** Skipping it is how the Stepper got built twice on the same day.

## Step 4 — The source, for things the index cannot name

An index lists exported components. It does not list a helper defined inside a
screen. When the thing you want is small — a row, a badge, a glyph, a preview —
grep the screens:

```bash
grep -rn "function [A-Z]" src/screens --include='*.tsx' | grep -i "<concept>"
```

If two screens already define it, that is not permission to write a third — it
is a finding. Say so.

## Step 5 — The classification check, before you conclude "gap"

This is the step that catches the expensive mistake, and it happens **before**
any search would have helped.

`BuilderTabNav` carried the comment *"DS-GAP: 3-step tab bar with completion
dots and enable/disable gating"*. That gap was real — the DS has no tab bar with
dots. But the thing being built was not a tab bar. **A tab you can lock behind
another tab is a stage**, and stages are what `Stepper` is for. Nobody searched
for a stepper, because the thing had already been named a tab.

So before concluding a gap, re-describe what you are building without the name
you arrived with:

| If you called it | Ask |
|---|---|
| a tab bar | can one item be disabled until another is done? → it is a **Stepper** |
| a card | is it a bordered content block? → **CardContainer** |
| a badge, pill, chip | does its colour mean a state? → **Tag**. A selection? → **Chip** |
| a dropdown | is it filtering a list? → **Filters** with `options` |
| an icon in a box | → **HighlightIcon** |
| an empty/error/failed state | → **EmptyState**, `compact` inside a widget |
| a widget type | is it a different *thing*, or the same thing drawn differently? Different thing → widget. Different drawing → variant |

## The verdict

Return exactly one, and say which step produced it:

**EXISTS** — name it, give the import path, and stop. Do not build.

**CANDIDATE EXISTS** — name it, give the import path, note that it has no spec
yet. Reuse it. If it genuinely does not fit, say precisely what is missing —
that sentence is what turns it into a spec later.

**GENUINE GAP** — say what you searched, what the closest thing is, and why it
does not fit. Then hand off: a new component goes to `experimental/` with a
`// DS-GAP:` comment naming the closest DS component, never straight to `ui/`.

## What good output looks like

Three lines, not a report:

```
CANDIDATE EXISTS — WidgetShapePreview in @/components/experimental/widget-parts
Draws widget shapes (kpi, bars, pie, donut, gauge, grid, rows) at any height.
Used by 3 screens. No spec yet; reuse it rather than adding a fourth renderer.
```
